# APEX-EM 笔记

> Banerjee, Moshtaghi & Chadha, arXiv:2603.29093 — *APEX-EM: Non-Parametric Online Learning for Autonomous Agents via Structured Procedural-Episodic Experience Replay*

## 1. 要解决的问题

基于大模型的自主 agent 在**程序层面基本无状态**：每接到任务都从头推理，即使刚做过结构相同的题。现有记忆（Reflexion 式反思、Voyager 技能库、MemRL 的意图–经验–效用三元组等）常见三类短板：

1. 经验多为扁平文本摘要，丢掉规划步骤、产物、迭代错误链等**可回放的程序结构**；  
2. 缺乏系统化的**正负双结局**学习（成功作正例、失败作带错误标注的负例）；  
3. 检索依赖表面语义相似，跨域「结构同类、措辞不同」的任务难以迁移。

**核心问题**：在不改模型权重的前提下，如何让 agent 在线积累、检索并复用**结构化程序–情景经验**，实现非参数在线学习？

## 2. 方法流程（完整工作流）

APEX-EM 把记忆做成 **Procedural Knowledge Graph（程序知识图，PKG）**，用 **PRGII（Plan–Retrieve–Generate–Iterate–Ingest）** 五阶段流水线跑每个任务；成功/失败经验都入库，后续靠语义 + 结构签名 + 图遍历混合检索做上下文学习。

---

### 阶段 A：经验在图里怎么存（PKG）

PKG 是带类型的图，节点可独立理解（自带标题、描述、id），世界事实变化时尽量只改实体、不改整段文本。

**五类节点**：

- **实体（Entity）**：公司、球队、API 端点等，带可测属性；事实更新只版本化实体，经验通过边自动指向最新版。  
- **经验（Experience）**：一次完整任务执行记录，标为成功或失败。  
- **子任务（Sub-Task）**：复杂题拆解后的子问题，挂到父经验下。  
- **操作（Operation）**：领域无关的推理原语（如实体消解、时间过滤、聚合），有序串起来形成**结构签名**。  
- **任务主题（TaskTopic）**：类别枢纽，连接相关实体与操作。

**边**编码时序（FOLLOWED_BY）、属性关联、跨域等价、经验–实体引用、语义相似、结构相似（最长公共子序列重叠 ≥ 0.6）、派生关系、计划版本 supersedes 等。新任务提到的实体会先做**实体解析**（嵌入检索 + 阈值 + 必要时大模型消歧），使不同说法落到同一操作节点，从而得到可比的结构签名。

---

### 阶段 B：一条经验长什么样（分层表示）

每条 Experience 不是一段摘要，而是多层「可查询」记录，大致包括：

1. **目标反思**：任务描述与嵌入、领域、约束、完成验收条件、目标侧操作签名。  
2. **程序反思**：可复用的分步模板（参数化 ENTITY/SOURCE/FILTER）、预算与步骤间检查点；更好执行可通过 supersedes 更新版本。  
3. **证据反思**：用到的网页/工具输出/库结果等，内容哈希寻址，带来源与可信度。  
4. **执行轨迹**：每轮意图（探索→精炼→纠错）、生成产物、执行结果、校验与反馈。  
5. **错误注册表**（失败时重点）：错误类别、发生步骤、根因、恢复策略与结果——把失败变成可查护栏。  
6. **补丁反思**：触发症状、对程序步骤的改动（插入/替换）、理由与效用变化。  
7. **评估层**：教师模型对正确性、效率、完整性打分，合成总分 q；再加定性反馈。质量门：q ≥ 阈值 → 成功，否则失败（领域 oracle 硬拒则强制失败）。

成功经验作**正例**；失败经验同 schema，但额外填满错误与补丁层，作**负例**。

---

### 阶段 C：PRGII 五阶段怎么跑一个任务

#### C1. Plan（规划）

对任务文本做结构化分解：

- 任务理解：意图、约束、期望输出、复杂度；  
- 实体发现：对照 PKG 解析实体；  
- Schema 发现：相关表结构/属性/API；  
- **假设结构签名**：抽象操作序列，供结构检索。

领域差异通过可插拔 DomainAdapter、Validator、PromptTemplate 注入。

#### C2. Retrieve（检索）

三条通道并行，再双轨分离重排：

1. **语义检索**：任务嵌入 vs 库中目标反思嵌入，取 Top-k。  
2. **结构签名匹配**：用最长公共子序列度量签名相似度；达到阈值即召回——即使措辞零重叠（如「对比 Curry 跨赛季三分」与「对比 Amazon 跨财季营收」可同签名）。  
3. **PKG 图遍历**：沿派生、用实体、结构相似等边扩 1–2 跳。  

候选拆成成功集 P⁺ 与失败集 P⁻，按语义相似、结构相似、图邻近、质量分、时效等加权重排；典型取约 **Top-3 成功 + Top-2 失败**，并带上子图与各反思层。

#### C3. Generate（生成）

大模型在「规划分解 + 正负经验」条件下生成可执行产物（代码、查询、动作序列等）。正例提供可改编模板与为何成功的教师反馈；负例提供约束违背点、错误类别与补丁，避免重复踩坑。

#### C4. Iterate（迭代）

生成 ↔ 领域校验器循环，最多 J 轮：校验失败则根据结构化反馈改产物；意图从探索到纠错演进；检测卡死重复失败并注入发散提示。有记忆时，失败经验让自检更有针对性。

#### C5. Ingest（入库）

领域 oracle + 教师打分得 q，过质量门后写入 Experience Memory：更新向量索引、PKG、元数据索引与完整经验存档。失败侧把自然语言反馈拆成错误注册表与补丁字段。整圈**不更新模型权重**，靠记忆变厚实现非参数在线学习。

冷启动可用少量人工种子经验、种子任务跑 PRGII，或离线用强模型灌库再在线用较小模型检索。

---

### 阶段 D：评测设定

在 **BigCodeBench**（代码）、**KGQAGen-10k**（结构化查询）、**Humanity’s Last Exam (HLE)**（多领域知识推理）上，用 Claude Sonnet 4.5 / Opus 4.5 作冻结骨干，与 MemRL 及 RAG、Self-RAG、Mem0、MemP、Reflexion 等在同一冻结骨干条件下对比。消融考察富教师反馈、迭代、各检索通道等对任务的依赖差异。

## 3. 达到的效果

- **KGQAGen-10k**：准确率 **89.6%**（CSR **95.3%**），无记忆约 **41.3%**，提升约 **+48.3** 个百分点，超过文中 oracle 检索上界（GPT-4o w/ SP，84.9%）。  
- **BigCodeBench**：从基线约 **53.9%** 到 **83.3% SR / 84.0% CSR**（约 **+29.4** pp），增益高于 MemRL 在 GPT-4o 上约 +11.0 pp。  
- **HLE**：实体图检索设定下约 **48.0%**（基线约 **25.2%**，**+22.8** pp）；结构签名有助于低语义相似时的跨任务迁移。  
- **消融**：富教师反馈对代码生成帮助很小，但对结构化查询关键（KGQA 约 **+10.3** pp）；带二元信号的迭代可部分补偿较弱反馈。
