# TriggerBench 笔记

> Zhang et al., arXiv:2606.23459 (2026) — *TriggerBench: Investigating Prospective Memory for Large Language Models*

## 1. 要解决的问题

长对话评测几乎全是**回顾性记忆（RM）**：用户明确提问，模型再去检索/回答。真正难的是**前瞻性记忆（PM）**——早期对话里埋下的约束/意图并未被明确委托成「请提醒我」，到后来某个触发出现时，模型要**自发**介入（提醒、警告、阻止风险），而不是等用户再问一次。

现有少数用「格式约束 + 做题」模拟 PM 的工作（如 Mittal 2026）偏指令遵从，不等于真实助手里「隐式约束 × 未来触发」的情境。

**核心问题**：如何在统一协议下，细粒度测量 LLM 的主动前瞻召回、误报率，以及对并发干扰的注意鲁棒性，并与同上下文的 RM 对照？

## 2. 方法流程（完整工作流）

TriggerBench 构造 **1265** 个 PM 任务，覆盖日常助手与专业工作流；每个场景按「约束 → 无关主题回合 → 触发 → 应否干预」组织。

---

### 阶段 A：任务骨架 \(C \rightarrow \Theta \rightarrow T \rightarrow A\)

1. **Constraint \(C\)**：早期自然陈述里埋下潜伏约束（未必说「remind me」）。
2. **Orthogonal turns \(\Theta\)**：若干与约束主题无关的对话/任务，拉长间隔。
3. **Trigger \(T\)**：当前回合出现看似无害的状态变化或请求。
4. **Action \(A\)**：模型应主动给出干预（提醒/警告）；负样本则应保持沉默。

---

### 阶段 B：五个 PM 维度

- **State-Tracking**：状态变化带来潜伏风险（如投屏后开银行）。
- **Temporal Grounding**：绝对/相对时间承诺，需自发 deadline 提醒。
- **Logical Adherence**：规则/政策约束与后续动作冲突。
- **Attention Recovery**：被打断后仍要记得未完成前瞻义务。
- **Safe Coding**：编码轨迹里的安全约束与危险操作触发。

---

### 阶段 C：对比变体与 RM 对照

- **Pos-Clean**：标准正例（应主动提醒）。
- **Pos-Over**：触发上叠加并发干扰请求（测注意力劫持）。
- **Neg-Clean**：风险已被消解或逻辑翻转（测假阳性/应沉默）。
- **Matched RM probes**：同一对话改成「事后追问」式 RM，严格对照被动检索 vs 主动干预。

刻意让多数维度上 \(C\) 与 \(T\) 词面/语义重叠极低，堵住「靠相似度碰巧召回」捷径。

---

### 阶段 D：评测怎么跑

在长上下文基线、RAG、Mem0、A-MEM、Letta 等设定上测 PM Acc / 假报；再做隐式 vs 显式委托、上下文长度缩放、与 AIME 推理负载联测。

## 3. 达到的效果

- PM 显著难于 RM：同上下文 RM 可到约 98%，PM 随长度明显掉点。
- 存在精确率–召回权衡：强推理提升主动召回，也可能「总是提醒」。
- 隐式约束、并发 overload 会大幅伤 PM；显式委托可接近饱和。
- 纯向量记忆（Mem0/A-MEM）在低重叠触发上易检索崩溃；Core Memory 常驻（Letta）在时间维更有利。
- 与 AIME 联测：同等长度下推理成功轨迹的 PM 更高——PM 可作「剩余推理预算」行为探针。
