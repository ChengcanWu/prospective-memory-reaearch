# PM-Failures-Mittal 笔记

> Mittal, TrustNLP 2026 / arXiv:2603.23530 — *Did You Forget What I Asked? Prospective Memory Failures in Large Language Models*

## 1. 要解决的问题

模型经常「内容写得对、格式/附加约束忘了」：既要完成 GSM8K 等主任务，又要遵守「全大写」「固定结尾句」等延迟约束。作者把这看作认知科学里**前瞻记忆**的功能类比——在执行进行中任务时，记得在正确未来点兑现先前意图。

**核心问题**：并发认知负载下，LLM 对可验证指令约束的遵从是否系统性下降？哪类约束最脆弱？简单 salience 提示能否挽回？

## 2. 方法流程（完整工作流）

不是 Virtual Week 式日程智能体，而是**组合式双任务范式**：主任务 + IFEval 风格可程序检查的格式/约束。

---

### 阶段 A：构造负载阶梯

将可验证约束与不同负载主任务组合：TriviaQA → MMLU → GSM8K → 摘要等。负载排序按操作难度，强调行为效应而非严格认知量表。

约束类型区分：终端约束（必须在输出边界兑现）、回避约束（禁止某模式）等。

---

### 阶段 B：确定性检查（无 LLM-as-judge）

全部用代码 checker 判合规与任务正确；三模型族、逾 8000 prompts。

---

### 阶段 C：缓解与堆叠

- **Salience-enhanced**：显式框定指令 + 尾部提醒，看能否恢复合规。
- **Stacking**：多约束叠加时联合合规如何崩。
- 测双向干扰：格式约束是否反过来伤害主任务准确率。

## 3. 达到的效果

- 并发负载下合规掉约 **2–21%**；终端约束最脆（可掉至约 50%）。
- Salience 格式常把合规拉回 **90–100%**。
- 干扰双向：一例 GSM8K 从 93% 掉到 27%。
- 多约束堆叠时联合合规可低于 50%。

**与条件延迟记忆的关系**：证明「延迟意图在负载下易丢」；但评测对象是**单轮指令约束**，不是助手日程上的 event/time cue + 隐藏通道监控。对 ProMem/PM-Bench 是机制旁证，不是同协议主竞品。
