# A-Mem 笔记

> Xu et al., arXiv:2502.12110 — *A-Mem: Agentic Memory for LLM Agents*

## 1. 要解决的问题

LLM agent 需要记忆系统才能利用历史经验，但现有方案（Mem0、MemGPT、MemoryBank 等）多依赖开发者**预先定义**存储结构、写入时机和检索规则；即使用图数据库，也常受固定 schema 和关系模板限制，难以随知识演化自发形成新组织方式。

典型困境：agent 学到一种新数学解法时，只能塞进预设分类里，无法建立创新性的跨域连接；固定工作流 + 刚性结构导致在新环境泛化差、长程交互效果衰减。

**核心问题**：如何设计一种**无需预设记忆操作**、能自主组织并持续演化记忆结构的灵活记忆系统，支撑 agent 长期交互。

## 2. 方法流程（完整工作流）

A-MEM 借鉴 **Zettelkasten（卡片盒笔记法）**：每条记忆是原子化「笔记」，通过动态索引与链接形成互联知识网络；一条记忆可同时属于多个「主题盒（box）」。系统分**写入（建库）**和**读取（答题/交互）**两条主线。

---

### 阶段 A：新交互到来时，怎么写入记忆

每次 agent 与环境产生新交互，依次执行三步：

#### A1. 笔记构建（Note Construction）

1. **捕获原始内容**  
   把本轮交互的原始文本 `c` 和时间戳 `t` 作为基础字段。

2. **LLM 生成语义属性**  
   用固定 prompt 模板，让 LLM 从「内容 + 时间戳」中自动生成：
   - **Keywords（关键词）**：核心概念；
   - **Tags（标签）**：分类标签；
   - **Context（上下文描述）**：比原文更丰富的语义理解。

3. **计算向量表示**  
   用文本编码器（论文实验用 `all-minilm-l6-v2`）把 `内容 + 关键词 + 标签 + 上下文` 拼接后编码成稠密向量 `e`，供后续相似度检索和链接。

4. **入库**  
   每条记忆记为：`{内容, 时间戳, 关键词, 标签, 上下文, 向量, 链接集合}`。遵循原子性原则——一条笔记只记一个自洽知识单元。

#### A2. 链接生成（Link Generation）

新笔记 `m_n` 入库后，自动与历史记忆建立关联：

1. **向量初筛**  
   用新笔记的 embedding 与库中所有旧笔记算**余弦相似度**，取 Top-k 最近邻作为候选（论文默认 k=10，部分任务类别会调参）。

2. **LLM 判定是否建链**  
   把「新笔记 + 候选近邻列表」喂给 LLM，分析是否存在共享属性、因果或概念关联；LLM 输出应建立的链接集合，写入新笔记的 `L` 字段。

3. **形成知识网络**  
   相关记忆通过链接互联，构成类似 Zettelkasten 的主题盒；与纯图数据库不同，**一条记忆可同时链入多个 box**，组织方式由内容驱动而非预设 schema。

#### A3. 记忆演化（Memory Evolution）

建链完成后，对 Top-k 近邻中的**每一条旧记忆**分别判断是否需要更新：

1. 把「新笔记 + 其余近邻 + 当前这条旧记忆」交给 LLM；
2. LLM 决定是否改写该旧记忆的**上下文、关键词、标签**；
3. 若更新，用演化后的版本替换库中旧条目。

→ 新经验不仅能追加，还能**反向刷新**已有记忆的理解，使网络随时间加深（如发现更高阶模式）。

---

### 阶段 B：用户提问或新交互时，怎么检索记忆

1. **编码查询**  
   把当前 query（问题或交互文本）用同一文本编码器转成向量。

2. **全库相似度检索**  
   与所有记忆笔记的 embedding 算余弦相似度，取 Top-k（默认 k=10）最相关条目。

3. **扩展关联记忆**  
   对被检索到的记忆，沿其链接集合自动拉取同 box 内的关联笔记，补充上下文。

4. **拼入 agent prompt**  
   把检索到的记忆（含时间戳、内容、上下文等）作为历史背景，交给 LLM agent 生成回答或决策。

> 与 agentic RAG 的区别：RAG 的「自主性」主要在检索阶段（何时检索、检索什么）；A-MEM 的自主性在**存储与结构演化**——记忆自己生成描述、自己建链、自己更新。

---

### 阶段 C：评测时怎么跑（LoCoMo / DialSim）

1. 按对话逐轮写入记忆（走阶段 A 全流程）。  
2. 对每个 QA 问题走阶段 B 检索，把 Top-k 记忆 + 问题拼 prompt，让基座模型生成短答。  
3. 指标：F1、BLEU-1（主榜），附录另有 ROUGE-L/2、METEOR、SBERT Similarity。

---

### 补充：实现与超参

- **嵌入模型**：`all-minilm-l6-v2`；**检索 k**：主实验 k=10，GPT-4o-mini 上 k 从 10 增到 50 时 Multi-Hop 等任务先升后平，过大 k 可能引入噪声。  
- **成本**：单次记忆操作约 1,200 tokens（LoCoMo/MemGPT 基线约 16,900 tokens，降约 85–93%）；GPT-4o-mini 平均处理约 5.4 秒/次。  
- **扩展性**：100 万条记忆时检索延迟从 0.31µs 仅增至 3.70µs，存储开销与 MemoryBank 等向量方案同为 O(N) 线性。

---

## 3. 达到的效果

- **LoCoMo**：在 6 个基座（GPT-4o-mini/4o、Qwen2.5 1.5B/3B、Llama 3.2 1B/3B）上，A-MEM 在多数类别优于 LoCoMo、ReadAgent、MemoryBank、MemGPT；非 GPT 模型上**全类别一致领先**；GPT 模型上 **Multi-Hop 至少约 2×** 于基线（如 4o-mini：45.85 vs MemGPT 25.52 F1）。
- **DialSim**：F1 3.45，优于 LoCoMo 2.55（+35%）和 MemGPT 1.18（+192%）。
- **消融**：去掉链接生成（LG）和记忆演化（ME）后性能大幅下降；仅保留 LG、去掉 ME 为中间水平；完整 A-MEM 最佳。
- **结构分析**：t-SNE 显示 A-MEM 记忆 embedding 聚类更 coherent，验证动态链接与演化有效。
